# OpenClaw 기억 시스템 벤치마크

2026-10-06. 기준은 실제 설치·실행한 **OpenClaw 2026.9.7**, 소스 커밋 [`c074824a27c96d3983043f9eeb33823cd1772d8c`](https://github.com/openclaw/openclaw/tree/c074824a27c96d3983043f9eeb33823cd1772d8c)이다. 온라인 문서는 바뀔 수 있으므로 설치 패키지의 문서와 해당 커밋의 검색 코드를 함께 확인했다.

결론: 기억의 용도와 수명을 구분하고, 원본을 보존하면서 검색 인덱스를 재생성하며, 검색 결과에서 원문으로 돌아갈 수 있게 하는 구조를 채택했다. OpenClaw의 전체 에이전트 기억 관리 기능을 Dingdong에 복제하지는 않았다. dots가 계획을 맡고 Dingdong이 프로젝트별 업무 기록과 실행 이력을 관리한다.

## 실제 검색 시험

개인 데이터와 기존 OpenClaw 프로필을 사용하지 않았다. 임시 디렉터리에 같은 합성 기억 32개를 넣고, 고정된 한국어·영어 질의 12개를 실행했다. OpenClaw는 실제 CLI의 `memory index`와 `memory search`를 호출했다. `provider: none`, dreaming 비활성 상태이므로 **임베딩·하이브리드 검색·자동 정리 성능 시험은 아니다**.

| 엔진                                  | 상위 3개에 정답 기록 포함 | 상위 3개 발췌에 정답 근거 포함 |
| ------------------------------------- | ------------------------: | -----------------------------: |
| 기존 Dingdong `0a1103d` 검색 알고리즘 |                     10/12 |                           9/12 |
| 개선한 Dingdong                       |                     11/12 |                          11/12 |
| 실제 OpenClaw 2026.9.7, FTS 전용      |                      8/12 |                           8/12 |

서로 다른 문서 최대 3개를 평가했다. 기록을 찾았어도 반환된 발췌에 근거 문구가 없으면 두 번째 지표는 실패다. 기존 Dingdong은 긴 운영 기록의 ID를 찾았지만 앞 2,000자만 반환해 뒤쪽 복구 지침을 놓쳤다. 개선안과 OpenClaw는 해당 구간을 반환했다. 개선안은 분해된 한글과 한글 복합어 검색도 통과했다.

영어 표현을 바꾼 `Who signs off on shipping?`은 개선안과 OpenClaw FTS 전용 검색에서 실패했다. 기존 부분 문자열 검색의 성공도 의미 이해를 증명하지 않는다. 한국어 재표현 질의에는 원문과 겹치는 검색어가 있으므로 이것 역시 의미 검색 검증으로 볼 수 없다. 이 작은 자료는 회귀 사례를 확인하기 위한 것이며, **Dingdong이 OpenClaw보다 전반적으로 우수하다는 근거가 아니다**. 처리량·대규모 검색·모델 답변 품질·개인 dots 계정은 이 시험의 범위에 포함되지 않는다. CLI 프로세스 시작 비용과 인프로세스 검색 시간을 비교하지 않았다.

- [고정 입력과 기대 근거](../tests/fixtures/memory-benchmark.ts)
- [재현 스크립트](../scripts/benchmark-memory.ts)

## 현재 구현 계약

1. 원본 기록과 인덱스 갱신은 같은 트랜잭션이다. 기존 DB는 시작 시 인덱스를 구성한다. 인덱스 재구성으로 확정 상태·이력·연결 정보를 바꾸지 않는다. 예전 기억은 읽을 때 장기 기준으로 취급하며 원본에 필드를 강제 추가하지 않는다.
2. 본문은 최대 1,400 UTF-16 코드 단위, 160 겹침으로 조각낸다. 정규화는 인덱스에만 적용한다. 출처 위치는 원본 문자열을 가리키며 모델 토큰 수를 뜻하지 않는다. 검색 후보는 최대 200개 조각, 결과는 최대 100개 기억이다.
3. `context_get`은 장기 기준을 최대 4개, 6,000자 예산 안에서 먼저 담고 질의 결과를 추가한다. 전체 기억 근거 배열은 메타데이터를 포함해 JSON 길이 14,000자·16개 이하다. 프로젝트·워크플로·실행 요약까지 포함한 전체 응답 길이 제한은 아니다. 장기 기준이 더 많으면 모두 상시 주입되지는 않는다.
4. `memory_search`는 전체 본문 대신 관련 발췌, 출처, revision, 위치와 `dingdong:memory:<id>@<revision>:<start>-<end>` 인용을 반환한다. `memory_get`에 동일 프로젝트·ID·revision·위치를 보내 원문을 재조회한다. revision이 바뀌면 최신 검색을 요구한다. 기본 재조회 최대 2,000자, 지정 시 최대 6,000자다.
5. 후보·잊은 기억·대체된 기억·만료된 기억은 일반 검색과 문맥에서 제외한다. 명시적인 `includeInactive`는 검토용이다. 잊기는 검색 제외이며 이력의 완전 삭제가 아니다.
6. 같은 요청 키로 이전 클라이언트가 재시도할 수 있도록 새 입력 필드는 선택 사항이다. 날짜를 명시하지 않은 수정은 기존 관찰 날짜를 보존한다. 새로운 관찰이라면 새 기억이나 명시적인 `observedAt`을 사용한다.

검증은 [memory.test.ts](../tests/memory.test.ts)에 있다. 원문 재조회·긴 본문의 근거 보존·기준 기억의 문맥 공간·시간 감쇠·한글·중복·프로젝트 격리·상태 필터·기존 DB 마이그레이션·원자적 실패 복구·요청 키 호환성을 다룬다.

## 추가로 가져올 설계와 현재 한계

OpenClaw는 서버가 기록한 출처 등급으로 정리 후보를 제한하고, 컨텍스트 압축 전에 기록을 남기는 기능을 제공한다. Dingdong은 인증된 호출자와 사용자가 제공한 출처 문구를 저장하지만, dots가 가져온 텍스트의 전체 출처 계보를 독립적으로 증명하지 못한다. 따라서 OpenClaw와 같은 출처 추적·자동 장기 승격을 구현했다고 보지 않는다. 참고: [Memory provenance](https://docs.openclaw.ai/concepts/memory-provenance), [Memory flush](https://docs.openclaw.ai/concepts/memory).

다음 확장은 ① 실제 사용자가 평가한 질의·정답 집합 확보, ② 선택 가능한 임베딩 검색과 비용·정확도 비교, ③ 원문 근거를 연결한 개선 후보의 묶음 검토 순서가 적절하다. dots 내부 압축 이벤트에는 접근하지 못하므로 현재는 작업 전환 시 `memory_write(layer: episode)`를 명시적으로 호출하는 도구 지침만 제공한다. 무인 dreaming이나 자동 체크포인트를 동작한다고 표시하지 않는다.
